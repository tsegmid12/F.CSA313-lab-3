

\# Лаборатори №3: Чанарын сценарио → SLO → k6 threshold



\*\*Хичээл:\*\* F.CSA313 — Программ хангамжийн чанарын баталгаа ба тест (2026)



\*\*Оюутны нэр:\*\* ЭНД НЭРЭЭ БИЧ  

\*\*Оюутны код:\*\* ЭНД КОДОО БИЧ  

\*\*Орчин:\*\* Windows 10/11, Node.js, Express, Grafana k6



\## 1. Зорилго



Энэхүү лабораторийн зорилго нь чанарын сценарио боловсруулах, тэдгээрээс Service Level Objective (SLO) тодорхойлох, улмаар k6 ашиглан автомат threshold тест хийх юм.



Тестлэх API нь гурван endpoint-той:



\- POST /cart/add — хурдан хариу өгөх endpoint.

\- GET /report — 200–400 мс хүлээлттэй endpoint.

\- POST /pay — ойролцоогоор 5% алдаа үүсгэдэг endpoint.



\## 2. Чанарын сценарио



\### 2.1 Performance сценарио



| Хэсэг | Тодорхойлолт |

|---|---|

| Тойм | Сагсанд бараа нэмэх үйлдэл хурдан ажиллах |

| Системийн төлөв | API сервер хэвийн ажиллаж байгаа |

| Орчны төлөв | 20 Virtual Users (VU), 1 минутын тогтмол ачаалал |

| Гадаад өдөөлт | Хэрэглэгч POST /cart/add хүсэлт илгээнэ |

| Шаардлагатай хариу | Сервер HTTP 200 буцааж, барааг сагсанд нэмнэ |

| Хэмжүүр | Хариу хугацааны p95 < 200 мс |



\### 2.2 Reliability сценарио



| Хэсэг | Тодорхойлолт |

|---|---|

| Тойм | Төлбөрийн үйлдэл найдвартай ажиллах |

| Системийн төлөв | Сервер хэвийн, төлбөрийн endpoint ажиллаж байгаа |

| Орчны төлөв | 20 VU, 1 минутын ачаалал |

| Гадаад өдөөлт | Хэрэглэгч POST /pay хүсэлт илгээнэ |

| Шаардлагатай хариу | Амжилттай төлбөрт HTTP 200, алдаатай үед HTTP 500 буцаана |

| Хэмжүүр | Төлбөрийн хүсэлтийн error rate < 8%, HTTP 200 хариултын хувь ≥ 92% |



\### 2.3 Availability сценарио



| Хэсэг | Тодорхойлолт |

|---|---|

| Тойм | Сервер гэнэт зогссоны дараа дахин ажиллах |

| Системийн төлөв | Сервер хэвийн ажиллаж байхад гэнэтийн crash үүснэ |

| Орчны төлөв | 10 VU, 2 минутын тест |

| Гадаад өдөөлт | Серверийг Ctrl+C ашиглан зогсоож, 10 секундийн дараа дахин асаана |

| Шаардлагатай хариу | Сервер дахин асаж, API хүсэлтүүдэд хариу өгч эхэлнэ |

| Хэмжүүр | Нийт хүсэлтийн амжилтын хувь ≥ 90%, сэргэлтийн хугацаа ≤ 15 секунд |



\## 3. SLO тодорхойлох



SLO (Service Level Objective) нь системийн чанарын хэмжигдэхүүнд тавих зорилтот босго юм.



| Сценарио | SLI | SLO босго | Цонх / нөхцөл |

|---|---|---|---|

| Performance | /cart/add latency p95 | < 200 мс | 20 VU, 1 минут |

| Reliability | /pay error rate | < 8% | 20 VU, 1 минут |

| Availability | Нийт амжилттай хүсэлтийн хувь | ≥ 90% | 10 VU, 2 минут, 10 секундийн зогсолт |



\### Босго сонгосон үндэслэл



\- Performance: 200 мс нь хэрэглэгчийн үйлдэлд хурдан хариу өгөх зорилтот хугацаа юм.

\- Reliability: Серверт 5%-ийн санамсаргүй алдаа суулгасан тул 8%-ийн босго нь бодитой хязгаар юм.

\- Availability: 90%-ийн босго нь 2 минутын туршилтад 12 секундийн хугацааны error budget-тэй тэнцэнэ.



\### Error budget тооцоо



Нийт хугацаа:



120 секунд



Зөвшөөрөгдөх алдааны хугацаа:



120 × (1 - 0.90) = 12 секунд



Иймээс availability SLO-ийн хугацааны error budget нь 12 секунд байна.
